# 导读：从一次训练走向整个系统

一行模型代码，可以同时牵动数学、存储、编译与网络。矩阵很大时，GPU 需要怎样把它分给许多执行单元？显存不够时，降低精度、重新计算和增加设备分别改变了什么？一个算子已经更快，为什么整个模型仍然没有明显加速？这本书沿着这些具体问题，介绍现代 AI 计算的软硬件体系。

全书从一次训练迭代出发。先认识张量、梯度与执行路径，再进入芯片和整机；理解单卡训练后，继续追踪框架编译与内核实现，最后把同样的数据流扩展到多卡和集群。学习顺序重视因果关系：先知道为什么需要一个机制，再看它怎样实现。

## 怎样阅读

如果你希望先建立整体认识，顺序阅读第1—14章，再读第25、29—36章。算子篇可以暂时观察图解和数值例子，等有兴趣时回头写代码。如果你已经使用 PyTorch 训练模型，可以从第10—18章进入，再结合第19—28章理解性能；如果你主要想写算子，建议仍先读第2、6—8章，建立布局、执行与数值基础。

| 阅读方向 | 建议路径 | 主要收获 |
|---|---|---|
| 系统认识 | 1—14 → 25 → 29—36 | 看懂计算、内存与扩展之间的关系 |
| 训练实践 | 1—4 → 10—18 → 附录贯穿实验 → 29—34 | 能提出可验证的训练与资源问题 |
| 算子开发 | 2、6—8 → 19—28 → 相关训练章节 | 从参考结果到内核、反向与性能分析 |

这些路径只是入口。CPU、GPU、编译器和网络的边界经常相互影响，遇到不熟悉的名词时，可以查术语附录，再返回当前案例。

## 三条贯穿线索

第一条是训练任务。从第1章的手算更新，到附录中的小型因果 Transformer，观察前向、反向、梯度累积、精度与检查点。合成数据实验有意避免下载大模型与数据集，让系统行为更容易复现；它不代表真实语言能力的训练成果。

第二条是算子。从向量加法、矩阵乘法，到 Softmax、RMSNorm、SiLU 与 Attention，始终把数学参考、边界处理、梯度和计时连接起来。NumPy 或标准 Python 实验用于验证数学，不模拟 GPU 的速度。GPU 示例需要匹配的设备和软件环境。

第三条是规模。从一张卡的显存账本，到参数分片、模型切分与专家通信，跟踪每项状态放在哪里、谁需要读取它、何时交换。纸上估算能够排除不合理方案，但最终性能仍须测量。

## 怎样理解书中的图

本书同时使用生成插画与精确图解。生成插画用来建立芯片封装、训练数据流和集群等概念场景，均标明“AI 教学示意”；它们不对应某个真实产品的内部布线、尺寸或实测结果。精确图解用可复现脚本绘制，解释地址、位域、时间线和容量，并注明假设。所有正文插图配有中文图注和读图说明。

看图时先认变量和边界。例如封装图上的大块只是概念区域，不能从面积推断某型号的缓存容量；矩阵方格帮助追踪分块，不一定按实际矩阵维度逐格绘制。真正的数值关系以正文公式、明确标注的精确图和来源资料为准。

## 现代内容怎样保持可靠

资料核验日期为2026年10月25日。正文把存储局部性、链式法则、通信下界等稳定原理，与工具版本、硬件支持矩阵和实验接口分开描述。现代路线包含 FSDP2、DTensor、Triton、CuTe DSL、cuTile、Helion、Pallas、低精度训练与新一代 Attention，但不会因为发布时间较新就替它作性能保证。

章节内的性能数字有三种来源：明确假设的估算、引用资料的结果、随书实际执行的验证。估算不冒充测量，引用不冒充本书复现。代码的具体执行范围见实验索引与审校记录；GPU 和集群实验需在对应硬件上进一步验证。

每章末保留本章参考资料，因此你可以单独阅读某一章，再沿官方文档与原论文深入。阅读这本书的目标，是逐渐学会追踪数据、识别约束，并设计能够推翻自己猜测的实验。
